# Gap analysis

This document lists the gaps that the evoparam specification is designed to close, and those it leaves open on purpose. It merges the "Gaps and opportunities" sections of the fourteen research axes with the weaknesses found in the inherited code base. Literature evidence is cited as `[LIT-<axis>-<n>]`, which resolves in `LITERATURE.md` (same numbering as the research files). Code evidence is cited as `[CODE §x]`, which refers to the sections of the code inventory (`research/code-inventory.md`):
- §0: summary of findings
- §4: known weaknesses relevant to CCEP
- §5: test coverage

**How to read the master table.**
- **id.** A stable identifier, `GAP-nn`.
- **gap.** What is missing in today's tools or practice.
- **who has it today.** The closest existing solutions and their limits, with keys.
- **what evoparam does.** Begins with one of three statuses. **Addressed** means that the specification commits to closing the gap. **Partly addressed** means that the specification closes part of it and the remainder is stated. **Not addressed** means that the gap is acknowledged and left open.
- **evidence.** Further keys that document the gap.
- **expected impact.** High, medium or low, with the reason.
- **REQ ids / spec section.** The requirements of the specification that close the gap, using existing identifiers only. Where no requirement applies, the column says "not covered", and a section number is given where the behaviour is specified without a dedicated requirement.

Under REQ-018, every gap marked Addressed must map to at least one requirement, one module, one test file and one validation item in the traceability section.

**Counts.** The table has 58 gaps: 49 addressed, 7 partly addressed and 2 not addressed. The gaps are grouped by theme:

- Component model and fitting engine: GAP-01–GAP-08
- Classical measures, single trials and reliability: GAP-09–GAP-12
- Response existence: GAP-13–GAP-14
- Stimulation artifacts: GAP-15–GAP-20
- Reference, polarity and spatial structure: GAP-21–GAP-23
- Trials, stimulation parameters and brain state: GAP-24–GAP-27
- Time-frequency responses: GAP-28–GAP-30
- Other domains and clinical-adjacent use: GAP-31–GAP-36
- Data and metadata: GAP-37–GAP-39
- Benchmark and simulation: GAP-40–GAP-41
- Reporting, provenance and outputs: GAP-42–GAP-45
- Ecosystem and software quality: GAP-46–GAP-49
- Inherited code: GAP-50–GAP-54
- Publication, licensing and adoption: GAP-55–GAP-58

## Top 10 gaps

The ten gaps below are ranked by expected impact on adoption, on scientific validity and on citation. Each one is the core of a cluster of related rows in the master table.

**1. GAP-02: no time-domain model of components over a slow background.**
- *Today.* Every general ERP toolbox scores geometric features of the average [LIT-erptools-2][LIT-erptools-17]. ERPparam fits peaks with a pre-stimulus mean as background [LIT-fooof-74]. The leading CCEP method is shape-free and explicitly cannot time its features [LIT-ccep-15].
- *Why it matters.* An explicit background is what made spectral parameterization useful [LIT-fooof-1]. Stimulation-evoked responses sit on decays and offsets that a peak-only model misreads.
- *What evoparam does.* It fits declared component shapes over declared backgrounds, with analytic Jacobians and variable projection (REQ-100, REQ-101, REQ-103). Every other module builds on this, including joint artifact-tail fitting (GAP-05) and shared shapes across channels (GAP-23).

**2. GAP-01: no released, documented, citable parameterizer of evoked responses.**
- *Today.* ERPparam is an unreleased fork with 4 stars and inherited tutorials [LIT-fooof-39][LIT-fooof-59]. The CCEP methods are MATLAB scripts for one modality [LIT-fooof-92].
- *The precedent.* The spectral precedent shows what a named, released method can become. Its paper has 2,533 citations (OpenAlex, 2026-10-07), 600 of them in 2025 [LIT-citation-1].
- *What evoparam does.* It ships one `fit` call for every modality, a release with CITATION.cff and a Zenodo concept DOI, and a name frozen at first release (REQ-001, REQ-002, REQ-391, REQ-394). This gap is first-mover: whoever releases first sets the vocabulary.

**3. GAP-13: no agreed response-existence test.**
- *Today.* Half of 187 CCEP studies do not say how they detected responses, and two-thirds of the rest use thresholds between 2.6 and 6 SD [LIT-ccep-11]. Threshold-defined responses barely reproduce between identical trains [LIT-variability-7].
- *What evoparam does.* It makes existence a calibrated permutation test, with onset and duration (REQ-130 to REQ-132). It also ships every published rule as a named, versioned registry entry, so that studies can be compared on identical inputs (REQ-133, REQ-135, REQ-137).
- *Why it matters.* Presence or absence is the primary result of connectivity maps. Scoring an absent component produces a noise peak.

**4. GAP-04: no parameter uncertainty.**
- *Today.* Neither the spectral parameterizer, nor ERPparam, nor the ERP scoring tools report an interval for a fitted or scored value [LIT-fooof-1][LIT-erptools-2]. The one Bayesian waveform model needs about 10 hours per subject and has no code [LIT-fitting-3].
- *What evoparam does.* Every reported latency, amplitude, width, onset, area and existence decision carries an interval or a p-value, and coverage is tested on simulations (REQ-006, REQ-116, REQ-230).
- *Why it differentiates.* Users have not yet asked for uncertainty in the spectral tool's tracker [LIT-needs-84]. Offering it therefore differentiates the package, and it answers the main published criticism of parameterization [LIT-fooof-53].

**5. GAP-03, with GAP-50 and GAP-51: heuristics instead of model selection.**
- *Today.* Component counts are set by thresholds, maximum peak numbers and deletion rules [LIT-fitting-13]. ERPparam's most recent bugs come from exactly these rules [LIT-fooof-88][LIT-fooof-89].
- *The inherited code.* The same mechanisms produce about 93% false peaks on pure noise and silent empty channels, and they delete genuine early N1s, so the inherited code found an N1 on 2 of 46 channels [CODE §0][CODE §4].
- *What evoparam does.* It replaces these rules with information criteria on whitened residuals, cross-validation and calibrated likelihood ratios. A test forbids deletion heuristics (REQ-004, REQ-104, REQ-107, REQ-112).
- *Permanent check.* The N1 case becomes a permanent CI test (REQ-113, REQ-114, REQ-017).

**6. GAP-40: no community benchmark with ground truth.**
- *Today.* Every methods paper builds a private simulation [LIT-erpmeas-2][LIT-erpmeas-43]. The spectral tool's own benchmarking issue has been open since 2023 [LIT-fooof-49]. Human raters agree on CCEP responses with a kappa of only 0.60, but the annotations were not released [LIT-ccep-8].
- *What evoparam does.* It defines seven tasks with versioned schemas, the published rules as baselines, a hidden split and a script-generated leaderboard (REQ-350 to REQ-357, REQ-392).
- *Citation value.* Harnesses are used more than they are cited [LIT-citation-11]. The benchmark is therefore published as a results paper, which gives the project a second citation target.

**7. GAP-11: single-trial parameters and latency jitter.**
- *Today.* No trial-level CCEP N1 latency SD has been published. The only single-trial CCEP study measured amplitude [LIT-variability-1], and CRP has no latency term [LIT-variability-2]. Scalp jitter estimators are MATLAB, unmaintained or code-less [LIT-erpmeas-14][LIT-erpmeas-15][LIT-erpmeas-27].
- *What evoparam does.* It fits per-trial shifts and scales with shrinkage, reports the jitter SD and the jitter-corrected amplitude, and refuses to invent jitter (REQ-150 to REQ-153).
- *Why it matters.* Trial variability carries information about epileptogenic tissue that averaging masks [LIT-variability-1].

**8. GAP-15, with GAP-16: stimulation artifacts.**
- *Today.* Python has one periodic-only port and scattered fragments [LIT-artifact-3][LIT-artifact-64]. MNE only interpolates [LIT-erptools-20]. The reference methods are MATLAB, several of them unlicensed [LIT-naming-36][LIT-naming-37].
- *What evoparam does.* It provides eight clean-room methods that never touch samples outside the declared window (REQ-060 to REQ-068). It treats masked samples as missing data in the fit, so that a component centred in the gap is still recovered (REQ-108, REQ-110).
- *Why it matters.* The earliest and most disputed features (N1, ERNA, early TEP peaks) live next to the pulse [LIT-artifact-7].

**9. GAP-42: reporting and methods text.**
- *Today.* Even with an optional methods template, only 56% of spectral-parameterization papers report settings and 30% report goodness of fit [LIT-fooof-4]. Only 3 of 72 well-described CCEP studies shared code [LIT-ccep-11].
- *What evoparam does.* Every result writes its own methods paragraph from saved provenance (REQ-008, REQ-123, REQ-338, REQ-340).
- *Why it matters.* This makes the results reproducible and puts the citation inside the workflow. Citation requests alone are followed only 13–26% of the time [LIT-citation-19].

**10. GAP-37, with GAP-46: stimulation metadata and MNE integration.**
- *Today.* Stimulation fields in BIDS exist only as examples [LIT-standards-2]. Deposits disagree on them [LIT-datasets-13], and MNE-BIDS cannot round-trip them [LIT-needs-53]. The spectral tool's only MNE integration was one example [LIT-fooof-23].
- *What evoparam does.* It harmonises and validates stimulation events, writes prefixed columns and contributes to the BIDS proposal (REQ-022, REQ-314, REQ-316). It fits MNE `Epochs` and `Evoked` directly and returns MNE objects (REQ-310, REQ-311).
- *Why it matters.* Without these, multi-dataset analysis and adoption inside the main Python ecosystem are not possible.
