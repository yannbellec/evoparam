Design principles
-----------------

.. glossary::

   One chain, separable steps
      The package implements the chain \*event → artifact → response → reliable numbers\*. Every step is a pure function or a scikit-learn-style estimator that accepts and returns the containers defined in §4.3, so each step can be used alone, replaced by a user's own code, or run on data that never passed through the earlier steps.

   Light core, optional extras
      The import ``import evoparam`` must succeed with only ``numpy`` and ``scipy`` installed (REQ-291). Everything else (``mne``, ``pandas``, ``matplotlib``, ``pynwb``, ``neo``, ``pyedflib``, ``pymc``/``numpyro``, ``cupy``, ``tqdm``, ``click``) is an optional extra loaded lazily inside the function that needs it, with an error message naming the extra to install.

   Numbers carry their provenance
      Every result object stores the package version, the full settings, the data hash, the random seed and the list of processing steps already applied to the input (REQ-294, REQ-331). Saving a result and reloading it reproduces the same numbers and the same methods paragraph.

   Units are explicit
      Time is in seconds everywhere in the public API (the convention of MNE-Python). Amplitude units travel with the data (``units`` attribute, default ``'uV'``). Stimulation parameters are stored with their unit in the column name (``stim_current_mA``, ``stim_pulse_width_us``).

   Polarity-agnostic by default
      Intracranial responses change sign with montage and depth [LIT-ccep-11], [LIT-ccep-8]. All detectors and shape fits operate on signed data but report ``polarity`` as a separate field, and every preset for intracranial data searches both signs.

   No inherited spectral vocabulary
      Class, function and parameter names describe evoked responses in the time domain. The ancestor tools are acknowledged only in ``NOTICE``.

      Name chosen in place of an inherited one (spec §4.4): ``ResponseModel`` (estimator) + ``ResponseFit`` (result). Reason: a class named like the package shadows the module in ``from evoparam import evoparam``; estimator and result are separated as in scikit-learn so results are plain data.

   GroupFit (renamed)
      Name chosen in place of an inherited one (spec §4.4): ``GroupFit`` (result) ; fitting via ``ResponseModel.fit_group`` / ``evoparam.fit``. Reason: same split.

   Component.params (renamed)
      Name chosen in place of an inherited one (spec §4.4): ``Component.params`` + feature fields. Reason: names say what the numbers are.

   min_fwhm
      Name chosen in place of an inherited one (spec §4.4): ``min_fwhm``, ``max_fwhm`` (seconds). Reason: one unit, two explicit bounds.

   max_components
      Name chosen in place of an inherited one (spec §4.4): ``max_components``. Reason: the model fits components, not only peaks.

   min_amplitude
      Name chosen in place of an inherited one (spec §4.4): ``min_amplitude`` (data units).

   detection_threshold
      Name chosen in place of an inherited one (spec §4.4): ``detection_threshold`` (in baseline-SD units) — used only for initial guesses, never as the final acceptance rule (§5.5.3).

   shapes
      Name chosen in place of an inherited one (spec §4.4): ``shapes`` (tuple of allowed shape names). Reason: several shapes may compete under model selection.

   overlap_threshold
      Name chosen in place of an inherited one (spec §4.4): ``overlap_threshold``. Reason: shape-agnostic.

   max_iter
      Name chosen in place of an inherited one (spec §4.4): ``max_iter``. Reason: scipy-agnostic name.

   onset_fraction
      Name chosen in place of an inherited one (spec §4.4): ``onset_fraction`` (fraction of amplitude defining onset/offset, default 0.10).

   gof.r2
      Name chosen in place of an inherited one (spec §4.4): ``gof.r2`` (coefficient of determination).

   ComponentWindows
      Name chosen in place of an inherited one (spec §4.4): ``ComponentWindows`` in ``evoparam.models.windows``. Reason: windows name components in time, not frequency bands.

   evoparam.sim.simulate_erp
      Name chosen in place of an inherited one (spec §4.4): ``evoparam.sim.simulate_erp`` (kept name), plus ``simulate_ccep``, ``simulate_erna``, ``simulate_tep``, ``simulate_animal_ep``.

Errors and warnings
-------------------

.. glossary::

   EvoparamError
      Subclass of ``Exception``.

   DataError
      Malformed container, unit mismatch, NaN outside masks. Subclass of ``EvoparamError``.

   ReaderError
      Unreadable file, missing sidecar, remote range request refused. Subclass of ``EvoparamError``.

   EventError
      No pulses found, inconsistent train structure. Subclass of ``EvoparamError``.

   ArtifactError
      Window outside epoch, template cannot be estimated. Subclass of ``EvoparamError``.

   FitError
      Optimiser failure after all restarts (never silently caught; see REQ-118). Subclass of ``EvoparamError``.

   NoResponseWarning
      Emitted, not raised, when the existence test is negative and a fit was still requested. Subclass of ``UserWarning``.

   ConvergenceWarning
      Trial fits or MCMC not converged (r_hat > 1.01, ess < 400, divergences > 0). Subclass of ``UserWarning``.

   SettingsError
      Invalid preset override (e.g. min_fwhm > max_fwhm). Subclass of ``EvoparamError``.

   EvoparamVersionError
      Subclass of ``EvoparamError``.
